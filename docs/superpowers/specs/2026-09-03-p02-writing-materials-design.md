# P02 写作材料与 TCNS 投稿工作台设计

## 1. 目标

在不把未证明目标冒充为论文结论的前提下，为 `P02_ET_ZO` 建立可追溯的写作材料层，并在现有桌面工作台增加一个有界、独立的“投稿与写作材料”页面。页面通过本机 `127.0.0.1:4176` 服务访问，但不直接读取或暴露用户研究目录的绝对路径。

## 2. 已确认的范围

- 论文类型：算法型研究论文。
- 当前状态：研究合同与证明脚手架，不是可投稿稿件。
- 主目标期刊：`IEEE Transactions on Control of Network Systems (TCNS)`。
- 冲刺备选：`IEEE Transactions on Automatic Control (TAC)`、`Automatica`。
- 条件型备选：`IEEE Transactions on Network Science and Engineering (TNSE)`；只有网络科学本身成为核心贡献时才考虑。
- 当前不恢复数值实验，不把早期 MATLAB 代理结果写成证据。
- 当前不做目录实时同步、数据库、自动投稿或外部文件上传。

## 3. 两类文献必须严格分流

### 3.1 同类论文、不同期刊：实质性写作证据

用途：

- 说明研究背景和问题缺口；
- 定位算法模块和理论工具的来源；
- 建立最近邻差异矩阵；
- 为相关工作、方法边界和贡献表述提供可核验引用。

每条记录至少包含：稳定标识、题名、年份、期刊、主题维度、可使用章节、可继承内容、不可继承内容、核验状态和官方来源。只有全文或明确的原始证据被核验后，才能支撑完成式论文主张。

### 3.2 目标期刊内的相似论文：版式与写作风格样本

用途仅限：

- 观察 TCNS 的篇幅和章节组织；
- 观察摘要、引言、贡献列表、定理、证明与实验的放置方式；
- 观察图表密度、附录组织、IEEE 引用格式和常见表达节奏。

这些样本不得被计入最近邻证据覆盖，不得据此声称算法新颖性、理论正确性或性能优势，也不得直接拼接其原文。

### 3.3 数据隔离约束

网页数据必须使用两个互斥字段：

- `crossVenueEvidence`: 同类论文、不同期刊，`usage = "substantive_evidence"`；
- `inVenueStyleSamples`: TCNS 同刊样本，`usage = "format_and_style_only"`。

验证器拒绝 usage 错配、同一记录同时进入两池、缺少稳定来源或把 style-only 样本标记为主张证据的输入。

## 4. 研究目录中的材料结构

在 `/Users/yangfan/Desktop/papers/研究项目/P02_ET_ZO/写作材料/` 创建：

1. `00_初稿生成与来源说明.md`
   - 记录初稿由哪些 PDF、项目决定、理论分析和代码状态生成；
   - 标明人工确认、模型整理与待核验内容；
   - 建立“来源 → 章节/公式/决定”映射与版本说明。
2. `01_目标期刊与同刊样本.md`
   - 记录 TCNS 官方范围、格式、页面限制和投稿前检查；
   - 保存 TCNS 同刊样本的版式与写作风格观察；
   - 显式声明这些样本不承担实质性证据角色。
3. `02_主张证据台账.md`
   - 每条主张记录状态、条件、证明/实验位置、允许措辞和禁止措辞；
   - 把“已固定的研究决定”与“已证实的论文结论”分开。
4. `03_相关工作与差异矩阵.md`
   - 只使用 `crossVenueEvidence`；
   - 比较在线性、网络、反馈、约束、通信、理论指标和实验口径；
   - 保留检索边界，不作全球不存在相似算法的断言。
5. `04_章节写作材料.md`
   - 按标题、摘要、引言、相关工作、方法、理论、实验、讨论和结论整理材料；
   - 每段记录唯一职责、可用证据和缺失输入；
   - 未证明或未运行内容继续使用占位语气。
6. `05_投稿缺口与任务清单.md`
   - 按算法、理论、文献、实验、写作和格式列出阻塞项；
   - 明确“完成条件”和证据位置。

现有 `论文初稿.md` 只增加候选目标期刊、投稿就绪状态和写作材料索引，不把目标定理改写为已证明结果。

## 5. 4176 页面

### 5.1 路由与导航

- 新增 `prototype/desktop/p02-writing.html`；
- 从 `prototype/desktop/p02.html` 的“写作与期刊”阶段和“写作入口”进入；
- 新页保留返回 P02、研究首页、方向探索和论文库的导航；
- 目标访问地址：`http://127.0.0.1:4176/prototype/desktop/p02-writing.html`。

### 5.2 页面信息架构

页面依次显示：

1. 稿件状态与 TCNS 候选定位；
2. 初稿生成来源与可追溯性摘要；
3. 两条并列但颜色、标签和说明不同的文献轨道；
4. 六份写作材料卡及其状态；
5. 主张—证据摘要；
6. 投稿阻塞项与下一步。

### 5.3 前端数据接口

新增 `prototype/desktop/p02-writing-data.mjs`，导出：

```js
export const P02_WRITING_DATA = {
  version: 1,
  updatedAt: "2026-09-03",
  manuscript: {},
  targetVenue: {},
  crossVenueEvidence: [],
  inVenueStyleSamples: [],
  materials: [],
  claimSummary: [],
  blockers: [],
}
```

同文件导出 `validateP02WritingData(value)`，对精确根字段、用途隔离、稳定 URL、唯一 `paperId`、状态枚举和私有路径泄露执行失败关闭校验。

新增 `prototype/desktop/p02-writing.mjs`，只消费通过验证的数据，按预定义容器渲染卡片和状态。生产代码不读取 Desktop 研究目录；网页内容是经审查的静态快照。

## 6. 服务器边界

私有本地服务采用显式静态文件白名单，因此必须把以下文件加入 `APPROVED_PROTOTYPE_FILES`：

- `p02-writing.html`
- `p02-writing-data.mjs`
- `p02-writing.mjs`

同一文件闭包还必须同步到发布包清单和测试期望：

- `exporter/paper-library/package-audit.mjs`
- `exporter/config/github-package-files.json`
- 对应的 package-audit 与 local-server 测试

根 `README.md` 与 `prototype/desktop/README.md` 增加新页面的访问入口，但不改变现有启动命令。

服务器仍只绑定 `127.0.0.1:4176`。网页数据不得包含 `/Users/...`、`file://`、Windows 盘符或 UNC 路径；研究目录的真实路径只存在于本地 Markdown 文件与 Codex 交付链接中。

## 7. 视觉与交互边界

- 复用现有桌面三栏结构和 `styles.css`；
- 只新增页面所需的少量样式，不重做导航或移动端；
- 两个文献池必须有显式用途标签和边界说明，不依靠颜色单独传达差异；
- 页面在 1440×900 与 1280×720 下无横向溢出，正文区域可滚动；
- 外部来源以普通链接打开，不自动访问、下载或上传任何文件。

## 8. 测试与验收

1. 数据模型测试：有效数据可通过；用途错配、跨池重复、缺来源、非法状态和私有路径均被拒绝。
2. DOM/路由测试：P02 可进入新页，新页可返回；两个文献池和六份材料均存在且标签明确。
3. 服务器白名单测试：三项新资源返回 200，未批准文件继续返回 404，符号链接保护不退化。
4. 内容审计：六份 Markdown 均存在 frontmatter、内部链接和显式边界；公式保持 Obsidian LaTeX 格式。
5. 浏览器 QA：在 4176 上检查路由、控制台、链接、滚动、1440×900 和 1280×720 截图。

## 9. 非目标

- 不声称稿件现在可以投稿；
- 不声称全球不存在完全相似算法；
- 不把 TCNS 同刊样本当作算法证据；
- 不生成虚构引用、DOI、定理或实验结果；
- 不实时读取或复制整个私人论文库；
- 不重写现有 P02 工作台的五阶段状态机。
