# 学术研究工作台论文库设计规格

**状态：** 页面结构与数据原则已由用户于 2026-08-27 确认；首个实施里程碑计划已编写，等待选择执行方式。

## 1. 目标

为现有桌面版学术研究工作台增加一个本地、只读、写作导向的论文库，使用户能够完成以下工作：

```text
浏览全部本地论文
→ 按研究方向与工作状态筛选
→ 阅读已有笔记
→ 区分阅读理解与可核验证据
→ 查看仿真、代码和结果产物
→ 将论文材料送入 P02 的算法、理论、仿真或写作环节
```

论文库不是原文件夹的网页镜像，也不是新的文献事实来源。它是一层覆盖现有异构目录的只读索引与工作界面。

## 2. 已确认的设计决策

- 桌面端是本轮唯一目标；验证宽度为 1280px 与 1440px。
- 论文库默认打开“所有论文总表”，顶部固定展示 P02 当前课题书架。
- 主内容使用紧凑列表，不使用大卡片瀑布流或文件夹树作为主视图。
- 右侧检查器显示当前选中论文的文件、缺口和 P02 用途。
- 单篇论文页面使用五个页签：概览、阅读笔记、理论证据、仿真复现、写作材料。
- 扫描论文根内符合纳入规则的全部论文单元，但不修改、重命名、移动或删除任何原始文件。
- 不使用数据库或后端服务。
- 不使用完成百分比；只显示真实存在、显式记录或已经核验的状态。
- 首个实施里程碑不实现自动下载、自动 OCR、自动总结、复杂智能体或知识图谱。

## 3. 私人本地版与公开版边界

论文库是本地私人工作台功能。当前事实来源默认位于：

```text
/Users/yangfan/Desktop/papers/
```

源目录不写死在程序中，而由本机私有配置提供：

```json
{
  "sources": [
    {
      "source_id": "main_papers",
      "path": "/Users/yangfan/Desktop/papers/论文"
    }
  ]
}
```

`source_id` 在换目录或换电脑后保持不变。用户只需更新 `path` 并重新构建，不修改程序代码。后续允许配置多个不同 `source_id`，但同一来源不能重复扫描。

扫描器仅以只读方式访问已配置目录。生成的索引、页面和审计文件位于网站工程的生成目录中，删除后能够重新扫描生成。

本地论文库与公开 Quartz 发布流程保持隔离：

- 本地论文库可以将已有 Markdown 笔记渲染成仅在本机访问的 HTML 页面。
- PDF 在首个实施里程碑只显示存在状态和原始路径，不复制、不嵌入网页。
- OCR 全文、全文翻译、私有代码和原始结果不进入公开站点。
- 将来若公开某篇笔记，仍需经过独立的发布白名单与脱敏导出流程。
- 本规格不改变既有公开站点的隐私规则，也不授权部署。

## 4. 总体架构

```text
现有 papers/论文/（只读）
→ 构建期 CLI 扫描器
→ 目录与产物适配器
→ 人工覆盖映射与冲突检查
→ 私有 paper-index.json + 审计 JSON
→ 私有本地静态论文库页面
→ 浏览器筛选、个人阅读标记与 P02 临时书架
```

浏览器不直接访问桌面文件系统。扫描和 Markdown 转 HTML 都发生在构建阶段，固定命令入口设计为：

```text
node exporter/scripts/build-private-library.mjs
```

构建只写入两个可删除目录：

```text
local_library_data/       # 私有索引、审计与受控笔记 HTML
local_library_output/     # 本地桌面页面
```

这两个目录必须被 Git 与公开 Quartz 构建排除。公开构建若检测到私有论文索引、绝对路径或本地笔记 HTML，必须失败。

`paper-index.json` 是构建产物，不是新的事实来源。论文身份、书目信息和正式研究状态只能来自现有文件中的显式元数据，或人工维护的私有覆盖映射：

```text
local_library_config/paper-overrides.json
```

覆盖映射是本地私人事实来源，不进入公开构建。数据优先级固定为：

```text
人工覆盖映射
> 文件内显式 frontmatter / 稳定短码
> 文件名与路径适配结果
> 保守空状态
```

### 4.1 目录适配器

适配器负责兼容以下现有形式：

- 标准 `Author (Year) Short-title` 论文目录；
- 与 PDF 同名的 OCR Markdown；
- `{短码}_论文精读.md` 与历史裸名精读笔记；
- `{短码}_推导过程.md`、`source_map.md` 与建模复盘；
- `{短码}_仿真描述.md`、代码对比、复现报告、脚本和结果目录；
- 纯中文翻译、`_中文翻译`、`_zh` 和历史备份；
- 学位论文母目录与章节级子目录；
- 一篇论文存在多个 PDF、OCR 或翻译版本的情况。

适配器只识别和记录，不整理原文件。每类产物使用数组保存，避免覆盖历史版本。

当前扫描根由本机配置解析为：

```text
/Users/yangfan/Desktop/papers/论文/
```

索引只保存 `source_id + relative_path`，绝对路径仅进入本地私有审计。整个源目录移动时，相对路径与论文身份保持不变；内部论文目录重命名时，显式 `paper_id` 或覆盖映射负责保持身份。

论文单元只允许以下三类：

1. 直接包含一个或多个 PDF 的论文叶目录；
2. 学位论文下直接包含章节 PDF 的章节目录；
3. 由人工覆盖映射显式声明的母论文容器。

同一叶目录中的多个 PDF 默认属于同一论文条目的版本数组；章节目录生成子条目并回链母论文。候选表、索引、网站工程、旧研究分支、空目录和不含论文产物的项目目录不进入论文条目。

### 4.2 稳定身份

稳定 ID 是每篇论文在工作台内的固定身份证，用于连接书签、P02 书架、理论证据、仿真记录、写作材料和反向链接。标题翻译、展示名称或源目录位置改变时，这些关系不应随之断开。

`paper_id` 的优先级如下：

1. 复用已有显式短码，例如 `Xi18-ADDOPT`；
2. 缺少显式短码时始终使用稳定相对路径哈希作为内部 ID；
3. 若作者、年份和算法缩写可靠，可另外生成 `AuthorYear-Slug` 作为展示别名，而不是内部身份来源。

显式 `paper_id` 重复属于阻塞错误。自动生成的 ID 必须通过路径摘要避免冲突。

学位论文章节作为独立条目，并通过 `parent_paper_id` 回链母论文，不将章节 PDF 误判为重复论文。

稳定性规则如下：

- 整个源根移动：只更新本机 `path`，ID 不变；
- 源根内目录重命名且已有显式 `paper_id`：ID 不变；
- 源根内目录重命名但只有路径哈希 ID：扫描审计提示身份可能变化，由覆盖映射将新路径绑定到旧 ID；
- 换电脑：复制项目程序，重新填写本机路径，保留相同 `source_id` 和覆盖映射；
- DOI 可以作为外部身份字段，但不能代替本地稳定 ID，因为部分论文或章节没有 DOI。

## 5. 最小数据模型

每条论文记录至少包含以下字段组。

### 5.1 身份与书目

```text
paper_id
slug
title_zh
title_en
authors
year
venue
doi_or_url
unit_type
parent_paper_id
```

`unit_type` 允许 `article | review | thesis | chapter`。

### 5.2 主题与方法

```text
topic_l1
topic_l2
research_scopes[]
method_tags[]
network_tags[]
problem_tags[]
contribution_role
```

`contribution_role` 用于区分奠基工作、关键方法转折、理论改进、应用研究和组合型工作。缺失时显示“尚未分类”，不能根据引用量或年份自动猜测。

### 5.3 原始定位与产物

```text
paper_dir
pdf_paths[]
ocr_paths[]
translation_paths[]
note_paths[]
derivation_paths[]
source_map_paths[]
modeling_paths[]
simulation_paths[]
code_compare_paths[]
script_paths[]
result_paths[]
reproduction_report_paths[]
```

### 5.4 文件存在性、正式状态与个人标记

```text
artifact_availability
source_status
evidence_status
reproduction_status
writing_material_count
warnings[]
```

文件存在性由扫描器生成；正式状态只能由显式元数据或人工覆盖映射提供：

- `artifact_availability`：PDF、OCR、精读、推导、source map、仿真、代码和结果是否存在；
- `source_status`：未检查原文、来源已定位、关键来源已核验；
- `evidence_status`：无证据卡、部分证据、核心证据结构已核验；
- `reproduction_status`：无材料、已有描述、有代码、已运行、有结果记录；
- `writing_material_count`：满足来源和用途要求的材料卡数量。

没有人工覆盖映射时，正式状态必须保守降级为：

```text
source_status: 未检查原文
evidence_status: 无证据卡
reproduction_status: 有代码，运行状态未记录（仅当扫描到代码时）
writing_material_count: 0
```

“有 PDF”不代表已读，“有代码”不代表复现成功，“有 source map”不代表核心证据已核验，“有精读笔记”不代表可直接写入论文。

用户在网页中切换的“未读、在读、读过”是独立的 `personal_reading_marker`，保存在浏览器 `localStorage`。它只服务个人队列，不改变正式状态，不参与证据、写作材料和默认研究贡献排序。

### 5.5 P02 用途

一篇论文可以同时服务多个用途：

```text
algorithm_mechanism
theory_evidence
simulation_baseline
related_work
```

论文进入某个用途只表示“被放入当前课题书架”，不表示其结论已经核验或可以直接引用。

## 6. 论文库总览页

### 6.1 本地路由

```text
/local_library_output/desktop/library.html
```

首个实施里程碑使用同页详情面板，不生成生产论文路由。经过索引结构验证后，第二阶段再生成：

```text
/papers/{slug}/
```

本轮不改变 Quartz 技术方向。桌面原型用于验证交互和信息密度；生产接入仍通过脱敏导出目录和 Quartz 构建完成。

### 6.2 页面结构

页面延续现有三栏桌面结构：

```text
左侧工作台导航 224–260px
中间论文库主内容 minmax(650px, 1fr)
右侧论文检查器 276–320px
```

中间主内容按以下顺序排列：

1. 页面标题、全局搜索和“搜索新论文”入口；
2. P02 当前课题书架；
3. 筛选与排序工具栏；
4. 论文总表；
5. 空状态或扫描警告摘要。

### 6.3 P02 当前课题书架

书架固定在列表上方，分为四个槽位：

```text
算法机制来源
理论分析来源
仿真比较基线
相关工作与写作引用
```

每个槽位显示论文数量和最多三篇短标题，超过数量使用“另有 N 篇”。点击槽位自动应用对应用途筛选。

首个实施里程碑的书架选择保存在浏览器 `localStorage` 中，仅用于当前本地工作台体验。它不修改 Markdown，也不改变正式证据状态。浏览器数据清除后可以重新选择；长期导出和跨设备同步不属于本里程碑。

### 6.4 筛选与排序

筛选分为五组：

1. 研究方向与方法标签；
2. 阅读状态；
3. 来源与证据状态；
4. 仿真与复现状态；
5. P02 或写作用途。

同一维度内多选取并集，不同维度之间取交集。

默认排序顺序为：

1. 当前 P02 书架成员；
2. 人工覆盖映射中的 P02 相关度；
3. 人工确认的贡献角色；
4. 可用写作材料数量；
5. 年份从新到旧。

缺少显式相关度或贡献角色时，不从标题、目录或标签猜测；对应排序键视为空并回退到年份和标题。

用户可以切换为标题、年份、研究贡献或证据状态排序。影响因子和引用量不作为首个里程碑字段，避免数据来源不稳定和跨领域误用。

### 6.5 论文列表

每行显示：

```text
论文短码、标题、年份
主题路径与方法标签
PDF｜笔记｜来源｜证据｜复现状态徽标
写作可用材料数量
当前 P02 用途
打开详情按钮
```

状态徽标必须同时使用文字和视觉样式，不能只依赖颜色。

列表第二行提供一条真实可用性摘要，例如：

```text
已有笔记；定理页码未定位；写作可用 0 条
```

## 7. 右侧论文检查器

选中列表行后，右侧更新为该论文的快速检查器，包含：

1. 论文身份：短码、标题、年份、主题与贡献角色；
2. 现有文件：PDF、OCR、翻译、精读、推导、仿真、代码与结果数量；
3. 当前缺口：缺笔记、缺来源定位、缺证据或缺复现记录；
4. P02 用途：四个可选槽位；
5. 操作：打开完整详情、复制原始路径、从当前书架移除。

右侧检查器不直接修改正式研究状态。首个实施里程碑不提供“标记证据已核验”等按钮。

## 8. 单篇论文详情页

### 8.1 页面结构

详情页继续使用三栏布局。中间顶部显示论文身份和五个页签：

```text
概览
阅读笔记
理论证据
仿真复现
写作材料
```

右侧固定显示文件清单、缺口、当前 P02 用途和返回论文库入口。

### 8.2 概览

显示书目信息、研究问题、核心思路、贡献角色、适用范围、局限和与 P02 的关系。

没有精读笔记时，只显示已确认的书目信息和“尚无阅读笔记”，不根据摘要或文件夹名称生成研究结论。

### 8.3 阅读笔记

渲染现有精读笔记和推导内容。阅读层允许保留解释与个人理解，但界面应区分：

```text
作者陈述
分析理解
待核验
```

阅读笔记不承担正式正文引用职责。首个实施里程碑不批量重写历史笔记。

### 8.4 理论证据

理论证据按结果对象展示：

```text
结论
成立条件
定理或引理编号
PDF 页码 / source ID
核验状态
适用边界
禁止外推
```

常见结果包括收敛性、收敛率、共识/跟踪误差、约束违背、通信复杂度和遗憾界。遗憾界只有在目标函数或数据随时间变化时才可能成为核心结果；动态网络本身不等于在线优化。

没有原文定位的项目统一显示“未检查原文”。

### 8.5 仿真复现

仿真页分别显示：

- 实验问题与数据；
- 对比算法和公平比较条件；
- 网络、预算、参数和评价指标；
- 代码入口、运行记录、结果图和复现报告；
- 当前失败或差异说明。

复现状态分开显示“有描述、代码存在、已经运行、结果有记录、与论文一致性已核对”。不存在总完成百分比。

### 8.6 写作材料

写作材料页只展示已经抽取的材料卡，不复制整篇笔记。材料卡至少包含：

```text
用途
可写主张或材料摘要
成立条件
source ID 与 PDF 页码
核验状态
限制与禁止声称
目标论文与目标章节
```

页面按 P02 的相关工作、算法机制、理论分析和仿真基线分组。

任何涉及“首次、唯一、最优、严格优于、保证”等强主张的材料，缺少来源、条件或核验时必须显示阻塞状态，不能计入 `writing_material_count`。

## 9. 缺失、冲突与错误处理

### 9.1 用户可见缺失状态

用户界面禁止显示 `Unknown` 和 `Not Reported`。JSON 内部可以使用稳定机器枚举，例如 `unavailable` 和 `not_checked`；渲染层统一转成明确中文：

```text
暂无书目信息
尚无阅读笔记
未检查原文
尚未建立仿真记录
有代码，运行状态未记录
写作材料 0 条
尚未分类
存在多个版本，待选择首选文件
```

### 9.2 扫描行为

- 无法识别完整元数据的论文仍进入索引，显示原目录和“待整理身份”。
- 单个不可读 Markdown 生成警告，不阻断其余论文索引。
- 显式 `paper_id` 重复、路径逃逸或生成路由冲突使构建失败。
- 多 PDF、多 OCR、多翻译或历史备份生成非阻塞警告，并保留所有路径。
- 失效文件路径显示为“文件已移动或不存在”，同时写入审计报告。
- 页面不得根据修改时间推断阅读、投稿、发表或核验状态。
- 扫描器必须解析 `realpath`；符号链接目标只有仍位于论文扫描根内时才可读取，外部目标只记录警告。
- Markdown 转 HTML 在构建阶段完成，生成相对链接；网页运行时不尝试读取 `/Users/...` 绝对路径。
- PDF 只记录存在状态和可复制的原始路径，不生成 HTTP 文件链接。

### 9.3 审计产物

扫描生成本地审计文件，至少记录：

```text
扫描目录数量
论文条目数量
标准条目 / 待整理条目
重复显式 ID
多版本文件
失效路径
未识别产物
生成页面数量
```

审计文件是生成产物，不进入公开搜索索引。

## 10. 搜索与浏览行为

本地搜索至少覆盖：

```text
中文标题
英文标题
作者
paper_id
研究方向
方法标签
网络标签
问题标签
```

搜索结果显示标题、年份、内容类型、主题路径、状态摘要和命中字段。首个实施里程碑只搜索元数据，不做 OCR 全文搜索。

键盘交互要求：

- `Cmd/Ctrl + K` 聚焦论文库搜索；
- 列表行和详情按钮可通过键盘到达；
- 筛选控件具有可读标签和选中状态；
- 页签支持方向键切换；
- 状态不依赖悬停或颜色。

`local_library_config/`、`local_library_data/` 和 `local_library_output/` 均不得被公开 Quartz 构建读取。生产接入 Quartz 时，使用经发布白名单批准的另一份数据适配层，页面信息架构和组件语义保持不变。

## 13. 测试方案

### 13.1 扫描器单元测试

fixtures 覆盖：

- 标准短码论文；
- 只有 PDF 的论文；
- 有精读但无 source map；
- 多 PDF / 多 OCR / 多翻译；
- 历史裸名笔记；
- 学位论文母目录与章节目录；
- 缺失书目信息；
- 重复显式 `paper_id`；
- 路径逃逸、外部符号链接和失效文件；
- 候选表、空目录和非论文项目目录不会进入索引；
- 同目录多 PDF 作为版本数组，章节目录作为子条目。
- 源根整体移动后，仅修改本机配置即可重建相同论文 ID；
- 内部目录改名且存在显式 ID 时关系保持不变。

### 13.2 数据语义测试

- “有 PDF”不得升级阅读状态；
- “有笔记”不得升级证据状态；
- “有 source map”不得自动升级核心证据状态；
- “有代码”不得升级复现成功状态；
- 写作材料数量只统计满足来源、用途和核验条件的材料卡；
- 目录名称和修改时间不得生成学术状态；
- 章节条目必须回链母论文；
- 人工覆盖映射优先于适配结果；
- 没有覆盖映射时使用保守状态；
- 私有索引或绝对路径进入公开构建输入时必须失败。
- GitHub 打包审计不得包含本机配置、真实论文产物或私有覆盖映射。

### 13.3 页面交互测试

- 搜索、同轴并集、跨轴交集和清空筛选；
- 排序稳定且不会改变状态统计；
- 选中论文时右侧检查器同步更新；
- P02 四槽位加入、移除和本地持久化；
- 个人阅读标记与正式状态视觉、数据均分离；
- 同页详情、首选笔记和空状态正确；
- 键盘切换和焦点可见。

### 13.4 桌面视觉测试

- 1280×720 和 1440×900 无页面级横向溢出；
- 论文表格内部可滚动，不挤压右侧检查器；
- 长标题、长短码和多标签可换行或截断并提供完整文本；
- 状态徽标同时包含文字和视觉样式；
- 页面控制台没有错误或警告。
