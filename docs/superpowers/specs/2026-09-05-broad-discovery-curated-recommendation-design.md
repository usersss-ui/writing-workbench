# 多来源检索与分层推荐设计

日期：2026-09-05

状态：用户已确认产品原则；本文件的实施细节待审阅。尚未修改检索页面或运行服务。

## 1. 用户可见的结果

保留一条主流程：确定方向 → 搜索本地及网上论文 → 标明本地已有材料 → 挑选候选 → 后续阅读。

**搜索尽量全面，推荐保持严格。** 期刊分区、中文期刊名单和代表性要求用于筛选重点推荐，不限制最初的文献发现范围。已知撤稿继续排除；年份和语言仍由用户明确选择，空年份表示不限。

搜索页默认显示“全部结果”，可切换“重点推荐”。两者使用同一份已加载结果，不建立两套论文库，不新增主导航。全部结果中保留不满足推荐门槛、证据不足、会议论文及预印本等线索；保留可见不等于推荐、归档或接受为论文证据。

本轮只处理检索、题录汇总、本地对照与推荐。PDF 自动下载、OCR、AI 全文分析、笔记生成、投稿判断和 App 打包不在本轮范围。

## 2. 已确认的研究偏好

- 英文期刊的重点推荐门槛：经过核验的 JCR **JIF Quartile** 为 Q1 或 Q2；不混用中科院分区、JCI Quartile、CiteScore 或 SJR。
- 中文期刊的名单准入仅包括《自动化学报》（Acta Automatica Sinica，ISSN 0254-4156）和《控制理论与应用》（Control Theory & Applications，ISSN 1000-8152）。这不是对其 JCR 分区的声明。
- 不将 IEEE/CAA Journal of Automatica Sinica 识别为中文《自动化学报》，不将 Control Theory and Technology 识别为中文《控制理论与应用》。相似名称不能自动取得名单资格。
- 满足较少研究条件的论文，只推荐少量有证据支持的代表作；满足较多条件的论文，可以放宽经典程度和引用量要求，但不放宽期刊门槛。
- 除上述名单外的中文论文仍可出现在全部结果中，不自动扩大中文推荐名单。
- 未核实的分区和研究条件标记“待核验”，不是“不合格”或“不相关”。

## 3. 现状与方案选择

现有 `discovery.mjs` 仅调用 `openalex-search.mjs`，每页 25 条；只有一个查询、一个游标和一个来源总数。`directions.mjs` 把方向选择压成普通关键词；`local-paper-match.mjs` 按身份核对同一篇论文，并不检索本地主题相关文献。`candidate-storage.mjs`、归档 API 和恢复协议均依赖真实 OpenAlex ID 与严格字段集合。完整浏览器备份目前为 version 2。

采用渐进整合：保留 OpenAlex 和现有归档链，在它们上方增加“检索批次／通用题录”层，并提供谷歌学术、知网的人工辅助检索与受控题录导入。

未采用的方案：

- 仅增加外部网站链接：入口简单，但不能把外部结果带回本地查重和筛选。
- 后台批量抓取谷歌学术、知网或 JCR：依赖尚未确认的访问授权和接口，不作为本项目的默认实现。

Google Scholar 官方说明支持引用导出，并明确不提供批量记录访问；因此“打开外部检索页”不得显示为“已经检索／同步完该来源”。[官方说明](https://scholar.google.com/intl/en/scholar/help.html)

## 4. 检索范围与条件组合

### 4.1 输入保持可解释

保留自由输入、年份、语言和排序。增加可展开的“本轮检索组合”，用户能够看到实际发送的每条检索式。手写高级检索式默认原样执行；只有用户明确选择扩展检索时才生成补充组合。

扩展检索使用带稳定条件 ID 的清单，每个条件可含同义词。一个条件内的同义词用 OR，独立条件间用 AND。同义词不重复计为多个研究条件；不凭字符串出现次数计算条件数。既有方向快照保持原样，不静默修改原有同轴 OR 语义；有歧义的转换先显示预览。无法可靠识别的自由文本仍可搜索，但不显示伪造的“满足 k/N 条”。

针对当前研究方向，检索组合按“主要研究问题 → 问题加网络条件 → 问题加方法 → 完整条件交集”组织，并提供单条件代表作检索。每批至多 6 条实际查询，未执行的建议保持可见，可按需继续；不枚举全部条件子集，不把尚未执行的组合计入覆盖范围。

主问题由明确的条件清单确定，并在预览中可修改。既有中文转换中破坏“在线”等词语、丢失分组的问题须一并修正；未能可靠转换时保留原词或提示人工修改，不能删除未知词后假装转换成功。

### 4.2 来源职责

| 来源 | 首版方式 | 不得误报 |
| --- | --- | --- |
| 本地论文库 | 查询现有题名、摘要／笔记预览和结构化标签；不上传本地正文 | 主题相关不等于与网上记录为同一篇；未搜索全文时不称“全文检索” |
| OpenAlex | 真实 API 查询，保留每个组合的分页 | 来源总数不等于整个领域总数 |
| Google Scholar | 用户主动打开检索链接、使用允许的引用导出后导入 | 不自动读取该浏览器登录态，不后台批量抓取 |
| 知网 | 打开正式检索入口并提供可复制的中文检索词；用户本人登录、导出题录 | 不承诺把未经验证的高级检索参数自动带入网站，不绕过验证或下载限制 |

首版导入格式限定为 BibTeX 和 RIS，提供格式说明与预览；不是所有知网导出格式都自动兼容。不支持的导出格式明确拒绝，可改用受控表单录入题名、作者、年份、DOI／公开来源网址。不得把任意 HTML、网页截图或自然语言当作已解析题录。

## 5. 批次、分页和结果身份

### 5.1 批次状态

每个检索批次记录条件快照、用户选择的范围、创建时间和状态；每个 `(provider, queryId)` 分别记录实际检索词、游标、来源总数、已接受页、加载量、错误和完成状态。

- OpenAlex 仍每次加载 25 条，一批最多 2 个并发请求；不无限自动翻页。
- 新检索使用新 generation；来源响应、导入确认、进度和 finally 均校验批次身份。旧请求不能覆盖新结果、修改新计数或解锁新操作。
- 失败来源可单独重试，保留其他成功结果；重复页及重试不重复累计。游标循环停止并说明原因，不能装作全部文献已穷尽。
- 页面主计数为“去重后已加载 N 篇”，另外列出本地／各来源／各组合的报告总数与已加载量。不能直接相加多个来源或组合的总数，也不能把页数或原始返回条数当成独立论文数。
- 切换全部／推荐不重新检索；继续加载可以改变推荐排序，须标明它基于当前已加载集合。

### 5.2 通用题录

新增来源无关的题录模型，保存内部 `result_id`、来源标识、公开定位信息、标准书目字段、各来源出处、检索批次、本地对应关系和筛选记录。来源出处至少包含 provider、取得方式（API／用户导入／本地）、查询或导入批次、取得时间和公开记录网址。

期刊身份补充来源 ID、刊名、ISSN／eISSN；这些字段不直接加入旧候选对象。引用次数保留来源与时间，缺失为未知而不是 0；不同来源引用数不相加、不直接当成统一评分。

语言、文献类型与撤稿状态分别保留来源和核验时间，缺失为未知。语言按书目元数据识别，不凭英文题名或期刊名称推定；指定语言时，未知记录放入可查看的“语言待核验”分组，不计为该语言已匹配结果。语言不限时正常保留。已知不符合本轮年份或语言范围的导入记录在预览中说明，不计入常规结果；范围信息未知的记录单列待核验。推荐规则依赖语言分流或期刊论文类型时，缺少依据不能自动通过相应门槛。

撤稿采用“来源报告已撤稿／来源筛查未发现撤稿／未核验”三态；任何可靠来源报告已撤稿即从常规结果与推荐中排除，并在批次摘要显示排除数量与依据。OpenAlex 的撤稿过滤记录为该来源、该次查询的筛查依据，不保证全球实时无撤稿。外部导入缺少依据时显示“撤稿状态待核验”，可保留在全部结果的待核验分组，但核验前不进入重点推荐；不能把未核验误写成未撤稿。

导入器产生内部标识，不能伪造 DOI、OpenAlex `W…` 或本地正式论文 ID。题录来源是用户声明且未验证时，界面说明这一点，不伪称通过对应平台 API 核实。

唯一且无冲突的规范 DOI／经核验来源身份可用于合并同一记录，并保留全部出处；题名相近、作者缩写、年份不同或预印本／刊版差异仅提示疑似。即使标识相同，遇到明显题名或标识冲突也暂停自动合并，保留原记录待核对。不得用模糊相似链把多个不同论文连续吞并。

保留来源级原始书目记录和内部 ID 的合并别名关系，候选与核验记录的引用保持可追踪。后到记录揭示既有合并冲突时，暂停该汇总的推荐与归档转换，标记需重新核对，不静默替换身份、迁移条件证据或删除候选。用户确认拆分后，只有能追溯至对应来源记录的证据才保留为已确认，其余转为待核验。

### 5.3 本地对照与候选边界

复用现有保守本地查重，另行展示本地主题相关结果。明确区分“本地未识别出这篇”与“本地没有相关方向”。

材料标记从索引的可用状态取得：PDF 已索引可查看、笔记已索引、仅书目信息、疑似重复、本地状态未知。索引失败时不能显示“本地没有／需要下载”；PDF 或笔记已索引也不等于已验证内容质量或当前 URL 一定可访问，打开失败应显示实际错误。

现有 OpenAlex 候选 v1、100 条容量限制、元数据归档 API、恢复协议和写入协调器保持不变。通用结果及外部候选使用独立状态；不能直接塞进 `candidateStore.add`。

只有主动从 OpenAlex 取得真实记录，并通过 DOI 等唯一身份核对、无冲突后，外部候选才可在用户确认时转换为旧候选格式。转换使用真实规范化 API 记录，而不是把导入记录附上一个看似合法的 W ID。仅题名搜索结果或用户粘贴的 W ID 不足以完成自动身份转换。

未匹配 OpenAlex 的外部题录也可保存、比较和导出，明确标为“外部候选，尚未正式入库”；首版不扩展其源目录归档协议。不得因这一限制把它从全部结果或外部候选中丢弃。

## 6. 推荐规则与核验记录

### 6.1 条件证据

把“检索命中”“关键词线索”和“研究条件已确认”分开保存。条件状态为已确认、线索待核验、明确不符合、未记录。只有已确认状态计入 k；未知不自动变成不符合。

确认记录须指向现有人工标签或可追溯的摘要／正文证据，包含证据定位、简短理由、核验方式与时间。本地既有标签可以显示为人工标签依据，不称其已完成本次全文审查。自动词匹配只能给线索；背景介绍、参考文献提及、否定表述不能自动确认为采用该方法。

本轮不新增 LLM 全文判定服务。用户可在一处简短的核验面板中确认／纠正证据；记录只作用于检索工作区，不反向覆盖已有正式分面与阅读笔记。

### 6.2 期刊门槛

JCR 核验记录至少包含刊名、ISSN 身份、JIF 指标、数据年、发布年（如已知）、学科、Q 值、来源网址／导入说明、核验时间和核验者方式。允许用户导入合法取得的 CSV 并映射列，或手动记录官方期刊详情中的数据；必须预览并确认，不凭刊名、影响因子或出版平台猜测分区。

首版以“用户核验记录”标注这些数据，不宣称接入实时 JCR API。缺失年份、学科、期刊身份或来源的记录不能成为确定推荐依据。错误或冲突的数据保留待核验，不静默选择更好的分区。

以下为待审阅的默认值：一轮推荐固定使用已导入证据中的最新数据年；没有覆盖的期刊不借用旧年份凑数。本项目主学科默认 Automation & Control Systems，可在规则设置中明确更改；不同学科的分区同时展示，但按事先选定的主学科判断，不从多学科中自动挑最好者。无适用学科证据时待核验。改变数据年或主学科须重算推荐并更新所显示的依据。

中文名单通过 ISSN 唯一匹配，或经用户明确核验刊名身份后生效；名称相似与 ISSN 冲突必须阻止自动准入。标记为“中文期刊名单准入”，不产生虚构的 JCR 字段。

预印本不能自行取得期刊分区；如关联到已经核实的正式发表记录，显示关联与版本区别。会议、学位论文等仍保留在全部结果中，但不自动通过本轮期刊型重点推荐门槛。

### 6.3 代表性与数量

期刊通过门槛后，再按经确认的条件数筛选。以下是待审阅的首版默认，不是已实施评分：

| 经确认的条件 | 代表性要求 | 默认展示 |
| --- | --- | --- |
| 1 条 | 有方法源头、长期常用基线或代表性综述的可追溯依据 | 每个条件最多 5 篇 |
| 2–3 条 | 有该交叉方向的重要方法／代表作依据 | 每个经核验条件组合最多 5 篇 |
| 至少 4 条且占已选条件至少 80% | 不要求高引用或已经成为经典，允许有直接贡献的新作 | 正常每页 25 篇 |
| 其余部分匹配 | 按交叉方向代表作要求处理，不因条件绝对数较大而误称高度相关 | 每个经核验条件组合最多 5 篇 |

“全部已选条件满足”是单独的事实标记，不取代上表：仅选 1–2 个宽泛条件时，全匹配也不能免除代表性要求。零条已确认条件的结果保留在线索中，不标直接相关。

代表性依据包含角色、理由和来源；不能只按引用总数给老论文自动盖“经典”章。引用数只是同来源、相近年份记录间的排序辅助，不捏造领域归一化分数。同分保持稳定排序，所有名额只约束推荐视图的默认展示，不截断全部结果或吞掉候选。推荐集合去重，一篇论文不因多个组合反复出现。

名额分组只使用排序后的已确认条件 ID 集合，不使用查询式或检索来源；同样的证据应取得同样的推荐待遇。本地召回和人工导入同样适用。每篇汇总论文只进入其完整已确认条件集合对应的一组，不同时占用子组合名额；组间按已确认比例、条件数、稳定组 ID 排序，组内按明确选择的排序规则及稳定结果 ID 排序。查询命中组合仅用于解释检索覆盖。

没有足够核验依据时，“重点推荐”应明确说明缺少分区／条件／代表性证据，并提供返回全部结果和补充依据的入口；不得用示例论文或随机分数填满推荐列表。

## 7. 保存、安全与兼容性

新建 `discovery_workspace` 状态 owner，保存检索批次、通用题录、外部候选、期刊核验和条件核验。来源结果与派生推荐分开保存，派生标签按规则版本重算。已有 OpenAlex 候选状态仍由原 owner 管理，使用交叉引用避免维护两份独立归档阶段。

完整状态包升级为 version 3，继续读取 version 1／2；旧备份没有新 owner 时保留当前新状态。新 owner 的导入必须先预览冲突，默认保留当前数据；不能通过更换备份版本覆盖用户已有写作草稿、阅读状态或候选。

首版建议上限：每个外部文件 2 MiB、500 条；工作区持久化最多 1,000 条题录，总序列化大小不超过 4 MiB。达到上限停止继续持久化并明确提示导出／清理，不静默丢弃旧内容，不称检索已到末页。清理批次需要用户确认，不能删除正式源论文或既有候选；用户可导出工作区备份。未成功保存时明确提示临时状态。

导入只解析受支持的文本语法：无 eval、无 TeX 执行、无 HTML 注入、无自动请求导入文件中的网址。限制字段长度和解析资源消耗，拒绝畸形嵌套、未知危险字段与原型污染。仅允许经现有安全规则验证的公开 HTTPS 记录链接；不保存凭据参数、学校账号、Cookie、会话令牌或原始认证导出。

不读取外部浏览器的认证信息，不绕过验证码，不后台下载付费全文，不写入源论文目录。所有真实题录、核验导出及本机设置保持私有，不加入 GitHub 公共包。UI 同时遵守来源数据库的许可与导出限制。

## 8. 建议代码边界

保持现有目录组织，采用职责分离的小模块：

- 检索组合：解析明确条件、同义词分组、组合预览、外部检索链接；适配 `directions.mjs`，不重写既有方向存储。
- 检索批次：调度、分页、代号隔离、原始计数与去重后计数；由 `discovery.mjs` 负责界面编排。
- 通用题录与导入：书目解析、规范化、真实来源和冲突；纯函数与外部 API 核验边界分离。
- 本地召回与身份对照：主题召回单独计算；复用并扩展 `local-paper-match.mjs` 的材料标记，不放宽确定匹配条件。
- 推荐规则：消费题录、核验与规则版本，返回资格、理由、缺少的依据和展示组；不执行网络请求或归档。
- 工作区状态：严格 schema、容量管理、可恢复导入；接入 `state-transfer.mjs` version 3。
- 期刊核验：记录身份、年度、主学科、出处和用户确认；不伪装成现成 JCR 接口。

`discovery.template.html` 与样式只增加当前页内的组合预览、全部／推荐视图和共用导入／核验面板。生成资产、服务资源白名单和包审计按现有构建路径更新，不能直接修改生成目录代替源文件。

## 9. 验收标准

1. 默认全部结果中，Q3/Q4、未知分区和名单外中文论文不会仅因质量门槛消失；已知撤稿不进入常规结果和推荐。导入语言／撤稿状态缺失时显示待核验，不伪称满足指定语言或已排除全部撤稿。
2. 五条件案例同时提供宽检索与交集检索，明确显示执行了哪些组合；手写式未被静默更改，同义词不增加条件数。
3. 本地相关论文可见，与外网同一篇查重分开；PDF、笔记、疑似和未知标记来自实际索引。
4. 相同 DOI 跨来源显示一条汇总与多个出处；题名近似／版本不同／元数据冲突不会错误合并。后到身份冲突不会把已有候选或条件证据转移给另一篇论文。
5. 多查询乱序返回、A→B→A、旧响应失败／finally、重复页重试、游标循环和单来源限流均不污染新批次或重复计数。
6. 谷歌学术／知网仅外跳时显示“待导入”；实际导入预览、确认、来源记录与本地对照完成后才显示已汇总。
7. 外部导入不能伪造 OpenAlex 身份进入旧归档 API；未核验外部候选可以保存和导出，旧候选阶段与恢复链不受影响。
8. JCR 数据年／学科／指标不符或缺少证据时不通过门槛；中文名单不匹配名称相近英文刊，不产生 JCR 标签。
9. 只有关键词或参考文献命中时不显示“已满足条件”；低条件代表作要求、新论文无最低引用限制和推荐去重均有确定性测试。相同证据不会因来源或查询组合不同而改变资格与名额组。
10. 不支持／恶意／超限导入、保存失败及用户取消均保留原状态；不会请求导入文本中的敏感链接。
11. 新版备份往返、旧版读取、冲突预览和容量错误不丢失任何既有 owner；全部结果容量限制不冒充源已穷尽。
12. 单元、DOM、受控浏览器测试使用合成公开题录和固定响应，不依赖实际登录、实时搜索命中数或真实论文库写入；最后做本机只读页面验收。

## 10. 实施前的明确边界

本文件落实已确认的原则，并提出首版默认值；不宣称已接通多源搜索、全自动语义分析或 JCR 数据。审阅通过后再制定实现顺序与测试计划。

首版将让外部题录进入同一检索／筛选工作区，但没有经核验 OpenAlex 身份的题录暂不自动写入正式资料包。后续若需要完全来源无关的正式归档，应单独设计身份、事务、恢复和迁移，不通过放松当前校验临时绕过。
