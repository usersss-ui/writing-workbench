# 论文项目目录接入 · 设计草案

日期：2026-10-23 · 状态：第 7 节第 1、2 步（登记与渲染、出处链接）已实施；第 3、4 步未开始

## 目标

论文项目目录里的内容由 AI 按 `paper-writing-workflow` 生成，由你审阅。平台的用途是**让你方便地看，并一眼看到每个点的出处**。

- **论文项目目录是唯一来源。** 稿件、文献清单、基准表、处理表都只存在于项目目录的 Markdown 文件里，平台不另存一份。
- **以呈现为主。** 把六个固定表头文件渲染成表格，把每个 `短码·位置` 变成可点开的出处，能跳到论文库里那篇论文的对应位置。
- **检查只留四项。** 只做那些人工翻文件很难发现、机器一眼就能查出的事。
- **写入只留一项。** 只有你点击“确认”时，平台往确认记录里追加一行。AI 能生成的东西，平台都不生成。

精简的原因：内容由 AI 生成，平台不需要模板、导出和生成功能；上一轮 Codex 开发“越齐全越好”，结果功能堆满却不知道怎么用。本版每一项都要说得出“你在什么时候会用它”。

## 范围

| 做 | 不做 |
| --- | --- |
| 读取已登记的项目目录，渲染固定表头的表格和 Markdown 正文 | 编辑任何文件（确认记录除外） |
| 出处链接：`短码·位置` → 文献清单 → 论文库原文 | 起草、审稿、分级、核查题录真伪（由 AI 按 skill 做） |
| 反查：某篇文献在哪些表、哪些小节被用到 | 生成模板、导出维度对比表 |
| 四项检查（第 4 节） | 拼稿、转 LaTeX/Word、编译 |
| 阶段总览与确认记录 | 自动迁移旧项目目录 |

## 1. 项目登记

私有配置 `local_library_config/paper-projects.local.json`，与论文库配置一样被 `.gitignore` 排除，不进公开包。

```json
{
  "version": 1,
  "projects": [
    { "project_id": "p03-example", "path": "/绝对路径/研究项目/P03", "layout": "paper-writing-workflow" }
  ]
}
```

- `project_id` 是稳定标识，移动目录只改 `path`。
- `layout` 只接受 `paper-writing-workflow`。没有声明 layout 的目录只列出文件，不解析表格。
- 生成的索引和页面只出现项目内相对路径。项目内容只放在本地生成目录，不进公开包。

## 2. 读什么

按 [固定表头](2026-10-23-paper-project-table-contract.md) 解析六个文件中的表；其余文件按 Markdown 渲染，复用论文库现有的受控 Markdown 和公式渲染。

| 文件 | 解析的表 |
| --- | --- |
| `03_范文对照/期刊基准表.md` | 取样、检查项、硬性规定 |
| `03_范文对照/潜在审稿人.md` | 作者组、检查项 |
| `03_范文对照/本刊写法清单.md` | 写法、术语译法 |
| `03_范文对照/小节范文映射表.md` | 映射 |
| `00_课题/课题卡片审稿.md`、`审稿/第N轮/处理表.md` | 意见、定位问题 |
| `相关论文/文献清单.md` | 文献 |
| `01_稿件/*.md` | 不解析表格；只识别正文里出现的短码，用于反查 |

表头对不上时，这张表显示“无法解析”，并原样显示 Markdown，不猜列的含义。

`P02_ET_ZO`、`DPZO-TVUD` 是旧布局，不登记就不显示；登记后也只列文件。

## 3. 出处链接（核心功能）

**正向：从一个点到原文。**

1. 表格中的 `短码·位置` 或〔位置〕被识别为出处。
2. 短码在文献清单中找到对应行，显示题名、角色和核实状态。找不到时标红（见检查 4）。
3. 文献清单行与论文库对照，规则与发现页相同：DOI 唯一才算本地已有。若短码与论文库编号相同但没有 DOI，只提示“可能是同一篇，需人工核对”。
4. 本地已有时，点击出处打开论文库的原文：
   - `p.页码` 打开 PDF 的对应页；
   - `§小节` 打开论文库该论文的“原文材料”页签，并在出处面板显示位置文字。实施时发现 OCR 标题写成“III.”“B.”等分级形式，无法可靠匹配“§III-B”，为避免把猜测当成定位，不做模糊匹配；
   - `定理2`、`式(12)` 等编号对象按原文显示，不做跳转。
5. 本地没有时，显示文献清单里的 DOI 和 PDF 文件名，不做猜测。

**反向：从一篇文献看它被用在哪。** 在文献清单的每一行，列出这个短码出现过的表格行和稿件小节。审稿时想知道“这篇文献撑着哪些说法”，一眼就能看到。

**按小节看。** 选中一个本文小节，同时显示它在映射表里的范文出处、本刊容忍度要点，以及本刊写法清单。这些是起草这一节前应该读的材料。

## 4. 四项检查

| 检查 | 你什么时候需要它 | 判定 |
| --- | --- | --- |
| 1. 需你决定的事 | 每次打开项目 | 处理表 `## 定位问题` 中 `决定` 为空的行置顶；`## 意见` 中 `决定` 为空的行列为“等你决定”；判“不成立”但 `依据` 为空的行标出 |
| 2. 不应起草的小节 | 起草前 | 映射表中 `本刊范文` 为空的行；`01_稿件/` 中没有映射行的文件 |
| 3. 只能“暂定”的检查项 | 看分级时 | 期刊基准表中全文本刊论文少于 5 篇，或某检查项的相关论文少于 3 篇 |
| 4. 出处断链 | 看任何表时 | 短码在文献清单中找不到；稿件引用了“未核实”的文献 |

原方案里的“每节一份现行稿”“课题卡片完整性”“产物过期”“归档命名”等检查，以及按钮式的 OpenAlex 题录核查，都不做了：这些由 AI 按 skill 自查，或者你看文件时自然就能发现。

## 5. 阶段总览与确认

总览按 skill 的步骤列出每步的产物是否存在，以及确认状态：

- **待确认**：文件存在，没有确认记录；
- **已确认**：有确认记录，且内容与确认时一致；
- **确认后已改动**：有确认记录，但内容已变，旧确认失效。

确认记录在项目内的 `02_规划与记录/阶段确认.md`，平台只往末尾追加：

| 日期 | 产物（相对路径） | 内容摘要（SHA-256 前 12 位） | 决定 | 范围与期限 | 备注 |
| --- | --- | --- | --- | --- | --- |

**这是平台唯一的写入。** 写入要求：
- 你点击“确认”后才写；
- 写入前核对你看到的就是当前内容；
- 只能写在已登记项目的根目录内，拒绝符号链接；
- 先写临时文件再改名；
- 失败时明确提示“未写入”。

关卡只提示，不阻止。

## 6. 与现有功能的关系

| 现有功能 | 处理 |
| --- | --- |
| 论文库 | 作为出处链接的落点，不改 |
| 发现页 | 不变；补文献时仍从这里检索和归档 |
| P02 写作页、P02 研究记录写作阶段、投稿项目正文 | 冻结，等试点跑通再决定是否下线 |
| 投稿项目的同刊范例（`references`） | 可供 AI 建期刊基准表时参考，不自动导入 |

## 7. 实施顺序

跟着试点论文的进度推进，目录里出现了哪一步的产物，就接入哪一步：

1. **登记与渲染**：配置、读取、六个文件的表格解析和 Markdown 渲染。最先有的通常是 `期刊基准表.md` 和 `文献清单.md`。
2. **出处链接**：正向跳转、反向反查、按小节看。
3. **四项检查**：随对应文件出现而接入。
4. **阶段总览与确认记录**：唯一的写入，最后做。

试点目录还没有产物的阶段，先用测试用的假项目目录开发和验证。每一步都要求：
- 全量单元测试和三套端到端验收通过；
- 新增文件进入打包白名单，打包审计通过；
- 生成物中没有绝对路径，私有配置和项目内容不进公开包。
